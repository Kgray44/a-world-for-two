# Native44 LIFE implementation proposal

This is executable **source**, outside the active bridge build. It replaces the two LIFE classes only in a future parent-owned candidate. It does not install itself, register a second listener, seed residents or modify active43. The frozen curation remains unchanged: sixteen inspected profiles, with the chorus-fruit/HARM Naturalist dragonfly disabled, and fifteen initially eligible identities. Their actual factory, environment and native hooks can still refuse a particular site.

`NativeHabitatLifeSupport.java` retains the shared `ArtisticEngineeringSupport.Interlock/Lease`, console-only authorization, exact private `world-tests/<stage>/world/RosewaterArtistic` scope, port25575, no players, current candidate/bridge/pack/checkpoint identity, immutable terminal journals, saved UUID census and durable world intents. There is no NoAI, tame/owner, profession, level, trade, variant, inventory or health setter, no copied entity NBT, no fake player, no teleport of existing residents and no permanent force or global idle wake.

## Source and native identity

All seven selected source JARs are checked against their actual loaded ModList paths and exact sizes, then hashed in a bounded queue:64KiB reads and approximately3ms per server tick. Size/time/file identity remains checked after hashing. This includes Fairy Tales as selected content even though it contributes no roaming fairy entity. Each actual resident also needs its exact registered class, category and class-resource hash. Minecraft Villager/Allay resource pins cover independently inspected named vanilla and NeoForge-patched21.1.262 artifacts; they are not hashes copied from an unreviewed native mismatch. Runtime Java21/Minecraft1.21.1/NeoForge21.1.262 is mandatory.

The old v1 request/recipe format cannot enter this v2 controller. The legacy three-argument policy query remains limited to the original four types; it cannot upgrade old admission to new species. New request classes/policy hashes must come from the final parent-built candidate, not hand-edited previous inputs.

## Actual habitat modes

Every resident carries a complete rectangular known field from authenticated saved **FULL** chunks. Bounds are at least5 blocks on each axis and at most4,096 cells per member,32,768 per batch; a dry45-cell witness is rejected. Sixteen residents and32 temporary chunks remain the batch maximum. The finite foot-coordinate guard covers the observed X912..1352/Z−1200..−616 study and its known-cell margin; it does not grant habitat authority. Each actual site also names a nearby member of the real connected-bank dataset, and the exact woodland source file is bound by hash.

| Kind | Additional literal habitat fields | Native admission |
| --- | --- | --- |
| `DRY` | Pets additionally require `roof`, `shelter_path`. | Actual sturdy dry footing, native body/entity collision and shelter; no assumed taming or wandering. |
| `AIR` | No invented flight flags. | The real native body plus a3×3×3 translated airspace core must be covered, fluid-free and collision-free. This does not claim later flight behavior. |
| `WATER` | `water_bounds` | At least5×2×5 connected unobstructed source-water cells and a real clear surface, with the fish's actual body in water. Native spawn rules still apply. |
| `SHORE` | `water_bounds`, `shore_path` | At least3×2×3 real source water, nearby dry footing and a connected body-clear dry exit of at least3 points. |
| `HOME` | `bed`, `job`, `roof`, `bed_path`, `job_path` | Exact living Villager, a real HEAD bed/HOME POI and free native job-site POI, shelter and two actual supported routes. No POI ticket or brain memory is claimed by this helper. |
| `MUSIC` | `roof`, `shelter_path` | Native default Ribbit profession and native finalization of its real current home, with shelter and body-clear circulation. No sorcerer role is fabricated. |

All modes include `kind` and six inclusive integer `known_bounds`. Routes contain up to64 integer standing-foot points, begin at the actual seed footing, remain in the known field and use connected supported steps with no more than one-block elevation changes. The native model's actual collision box and full dry headroom are queried. These geometric routes and POI availability do **not** prove the villager has subsequently acquired its job or successfully navigated; ordinary player-observed AI remains necessary. Non-sturdy decorative stairs may be refused rather than treated as a valid shortcut.

`prepare.py` conservatively accepts only literal source-water blocks during saved preflight. The native controller independently checks real fluid states, source status and collision shapes. Heightmaps, including OCEAN_FLOOR above canopy, do not prove water depth. No water fill, plant removal or terrain flattening is performed to make a site pass.

## Protection and native defaults

The complete2760-cell R5 reservation is independently bound by its sorted coordinate hash `e376a4e7c40fd51e26c7b983d05599d8e688bd27c3532d8c130bfdf4bdb41491`, so a harmless dry-checkpoint metadata rebind does not trim its footprint. All R5 AIR, statue, plumbing, arrival views and routes receive their full five-metre column skirt. The required `awft-life-safety-index:1` supplies exact owned references to current motion/navigation native plans and the explicit future cable/station X/Z reservation. All addressed native cells, including AIR, retain a five-metre skirt; the existing cable mask already carries its skirt. An X/Z reservation is never converted to invented AIR states. Actual resident bodies, water volumes and routes must avoid this protection.

The safety index is deliberately for motion/navigation reservations, not every house interior: reviewed town NPCs belong in usable houses/courts. Real furniture, doors and structure collisions remain present and are checked against the native model. Root must review that the index contains every current working envelope and rebind it after construction changes.

New pets must remain natively untamed/unowned. A new Doggy Talents dog must already be DOCILE with attack disabled; those values are observed, never assigned. Ribbits must retain their ordinary NITWIT/music default and finalization must establish their actual current home. A new allay stays empty-handed with an empty inventory. Existing legitimate player ownership, mode, held items, professions and trades are preserved; new-factory tests are not reapplied as resets to old residents.

## Spawn, idempotence and cleanup

New objects come from the real native factory. `SpawnPlacements.checkSpawnRules` uses the actual level random source, and normal `EventHooks.checkSpawnPosition` and `EventHooks.finalizeMobSpawn` remain active. The latter's null final parameter is normal `SpawnGroupData`, not a fake-player argument. The patched native cancellation flag, UUID, body, defaults and habitat are checked again after finalization and before `addFreshEntity`.

The world stores one durable population namespace/curation authority and a64-resident limit including all earlier proposed species. Per-species caps apply across batches, counting unresolved intents as well. Existing or foreign namespaces are not silently replaced. Every actual add has a flushed per-UUID intent first; successful native identity readback adds an immutable admission marker. A failed/unknown add, unloaded old UUID or partial ledger remains uncertainty, never permission to duplicate. Planned villager beds/jobs are retained across batches to prevent empty-world overbooking before ordinary AI claims its own POIs. This bookkeeping does not assign a villager's memory or profession.

Failures retain real residents and ledger evidence. Receipts separately record attempted world/ledger writes and possible mutation, so a partial file write or native add cannot be hidden by a zero success counter. Failed ticket removals retain their exact handles and lease, with an explicit cancel cleanup retry; there is no idle retry or journal-spam loop.

## Producer and parent handoff

`prepare.py` reads an actual reviewed `awft-life-sites:2` file containing1..16 individual sites. Each site has only `name`, `entity`, `feet`, `roam_bounds`, `habitat`, and `bank_anchor`; no NBT, owner, NoAI, profession or claimed native-result field is accepted. It reads the verified stopped backup, complete saved entity census, final R5 mask, whole-bank source and safety index, then writes a new private preparation folder. Its verification-only habitat plan is not a placement plan. Existing v2 recipes may be retained for later inspections; v1 cannot silently upgrade.

The default operation is `inspect`. `seed` additionally needs exact current construction/function/art/habitat approval and the actual completed native habitat verification; the controller checks the immutable completion digest, exact plan coverage, status, freshness and cleanup. The producer neither installs the request nor launches Minecraft. All preparation failures receive a separate private failed receipt where the output scope is valid.

Parent integration replaces both LIFE classes atomically, retains the existing one-instance command/tick/stop/busy wiring, compiles the final candidate and prepares inputs using its exact class hashes and active pack. Install only the explicitly reviewed private request. Do not deploy the standalone probe classes or change the active43 files while reviewing this proposal.

Pinned API compilation, pure policy cases and producer fixtures are source evidence. Actual fifteen-species class/resource linkage, hook/cancellation behavior, water/flight/POI admission, native pilot, idempotence, ownership preservation, restart/cleanup, real AI, native appearance and CPU/RAM/MSPT remain unproved until their separate parent-owned private tests. No residents have been seeded by this proposal.
