# First native urban relocation proposal

This original helper is **outside active bridge source**. The owner requires the
drawn whole-city plan to be reviewed first. No city-map approval, native move,
inventory conservation result or restart acceptance is asserted by this source.

It exposes only one fixed Pippin room:320cells, seven current native block
entities, cardinal translation−13,0,0. The source geometry and original capture
are pinned to the exact06 checkpoint; a later current checkpoint can rebind the
same semantic geometry only with new actual native proofs. The helper accepts
no other AABB, arbitrary command, NBT loader or inventory writer.

The source and destination each have one original ordinary-cover cell. These
must be cleared by separate narrowly admitted geometry operations after the
owner's city-map approval, then receive real native full-source/destination
proofs. The helper itself never clears cover or seeds an empty destination.

## Parent integration

Copy only `NativeRelocationSupport.java` into the actual bridge source after
review. Its nested durable primitive is compiled automatically. The probe is
test source and must not be included in the runtime JAR.

- Construct `new NativeRelocationSupport(candidate, bridge, sharedInterlock)`.
- Call `commands(RegisterCommandsEvent)` from the existing command hook.
- Include `busy()` in the shared native-operation exclusion.
- Call `stop()` before level close. Call `tick(server)` for bounded owned
  cleanup/publication retries only; it never repeats a world operation.
- Add only the typed `awftrelocate inspect|move|inspect-moved <bundle> <sha256>`
  forms to the Control Room's reviewed console allowlist. Do not expose generic
  clone commands through the dashboard.
  `awftrelocate cleanup` only retries this helper's owned release/publication.

`tools.native_relocation_request.geometry` produces private source geometry,
two-cover preparation proofs and prospective post-preparation states. It never
installs a request. Its `bind` function additionally requires the actual owner
map-review record, current pack/bridge/JAR classes, marked native source,
destination and support proofs, and—for a move—a fresh successful native
inventory inspection from the same runtime. Request installation/activation and
all world actions remain parent-owned.

The owner review must be actual trusted evidence with format
`awft-owner-city-plan-review:1`, boolean `approved:true`, the exact eastern
layout SHA and an allowed operation `pippin-native-relocation-prototype`.
Source geometry or a synthetic test is never this approval.

## Native gates and conservation

Only the actual permission4 native console, private25575 artistic world, exact
world identity, current owner/checkpoint, running pack and actual compiled class
bytes are admitted. All12 surrounding persisted FULL/entity-loaded chunks must
already exist in memory. The helper makes no load/generation/ticket/future
request and fails if readiness is missing. An empty server and the shared lease
are checked again immediately before the operation.

Every actual source, destination and support state is compared in full on the
server thread. Native shapes/collision bounds must fit the source capsule;
actual survival/support, complete door halves, actual BE membership and entity
occupancy are checked. Render-mesh closure beyond native shape APIs is not
certified; unknown or refused model support needs explicit review, not truncation.

Native BE class/type/hash and the complete typed native saved custom data are
captured. Five of the seven expected objects implement the real Container API;
all actual slots and counts are observed. Every nonempty stack's registered,
persistent native components are encoded through the actual registry-aware
codec. Unknown/transient components or unresolved loot refuse the move.
Globe and sign have separately reviewed non-Container roles; absence of an
`Items` key is not treated as proof of empty storage.

After a fresh inspection and same-tick repeat checks, a stable world/room
transaction creates and fsyncs a once-only intent. The exact registered vanilla
`CloneCommands` implementation then runs the one fixed `replace move` command.
No fake player, raw-NBT reconstruction, inventory debit/restock or component
normalization is used. Full source AIR, exact destination states/survival,
native class and slot/component conservation, and full custom-data equality
are required. Only top-level native XYZ metadata changes to its explicit new
coordinates. Any legitimate but unexpected native shape/state change still
stops and quarantines; expected states are not silently fitted afterward.

Completion is written/fsynced only after all conservation checks, with an intent
hash and completion marker. Any existing intent—including an interrupted one—
blocks replay. Unknown/partial outcomes retain the exact world and a quarantine
record; there is no automatic rollback or missing-object repair. Read-only
`inspect-moved` checks actual persisted content; restart evidence is reported
only when the native PID/start identity differs from the completed process.

All detailed snapshots remain private. No seed, accounts, world data or typed
inventory receipts belong in Git. The normal immutable NativeJournal receipt
records cleanup; owned chunk tickets, generation requests and futures are zero.
Failed receipt publication stays busy, and failed lease release retains its
reference. One immediate attempt permits at most two automatic retries spaced20ticks;
explicit cleanup/stop can make another bounded attempt. The original operation
measurement time is preserved. No cleanup retry can invoke clone again.

Preparing geometry for a later stopped checkpoint independently rereads all720
source/destination/support cells and all seven complete typed saved tags from
the authenticated archive. It refuses any difference from the original06
capture. This is not a metadata-only backup rebind, and it does not replace the
fresh native entity/model/class/slot/component inspection.

## Verification limits

The proposal compiles against the actual pinned named Minecraft/NeoForge API.
The bounded Java ledger fixture executes the production durable primitive and
checks real CREATE_NEW/fsync bytes, existing and partial-intent refusal, and
oversized/empty refusal, without initializing any Minecraft class. Python tests
cover actual marked-proof/plan/status binding, explicit city-map review and
duplicate class-resource refusal. A changed saved voxel or a numerically equal
inventory Slot with a different NBT width is held by the fresh-capture test.
These are source/API/fixture evidence only.
Actual dedicated-world inspection, model closure, native clone, conservation,
normal restart and final artistic screenshots remain unrun.
