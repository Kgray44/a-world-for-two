# Native bee-nest growth admission proposal

This isolated source patch fills the specific active43 gap: old block entities were compared, while newly native-created BEs lacked their own admission rule. It changes neither active43 nor the frozen native44 fauna proposal. `prepare_source.py` verifies both exact frozen tree source hashes and produces four derived Java sources in a new private staging directory for root to review and integrate atomically.

The scoped setter admits a desired BE only when the actual qualified descriptor has a native nest-producing branch, the original cell is AIR, the desired block is exactly `Blocks.BEE_NEST`, and its honey level is zero. All existing BE, tree, fluid, protection, known-field, exact-write and latched recovery restrictions remain. No crafted beehive, modded BE, arbitrary inventory or old nest can enter this exception.

`TreeBeeAudit` checks the actual pinned native block, BE, occupant, stored-data and removal class resources. A successful synchronous grow may contain at most one new exact native `BeehiveBlockEntity`/BEEHIVE type, at an owned attempted cell inside the write field. Its actual save codec must show two or three ordinary bee occupants, only `id=minecraft:bee` entity data, native0..598 occupation ticks and minimum600. A native `Occupant.create` record has no UUID: the helper records that fact, never manufactures an entity UUID or calls release/createEntity. The real UUID is generated later by ordinary native release. Existing BEs are compared byte for byte. Unexpected components, custom data, occupants, fire or changed live entities refuse admission.

Read-only inspection of the pinned native removal chain proves `BeehiveBlock` and `BaseEntityBlock` have no `onRemove` override. Inherited `BlockBehaviour.onRemove` only removes the old BE when its block changes; it neither drops the hive nor releases bees. `storeBee` only appends its actual native stored record. By contrast, fire can trigger native release through `setChanged` or `updateShape`; the proposal explicitly rejects nearby fire and compares the complete bounded loaded-entity UUID/type/class/position census before and after growth/removal. This is read-only observation, without a global wake or forced simulation.

Before failed-growth restoration removes any newly created hive, the helper first validates every new BE and verifies that no live entity was released or changed. Partial hives may contain zero to three ordinary native records during failure handling. Restoration still uses the original guard's exact attempted-cell preimages and flags2|16, without drops or player destruction. It compares the original BE map and live-entity census again **inside the restoration try**, before the clean-world latch is cleared. Unknown BEs, broken audit evidence, unexpected live bees or an unproved removal leave the private quarantine in place; no resident is deleted to manufacture recovery.

Native bee outcomes are archived with actual nest positions, native BE hashes and stored slot counts. They must enter the final whole-area LIFE census/resident budget alongside the fifteen selected species, without treating stored no-UUID records as already spawned UUIDs or counting a later released bee twice. This patch does not silently increase the sealed native44 population cap or modify its ledger. Root must bind that final census when preparing the cohort; old BE/bee inventories are never rewritten.

The private pinned-API build compiled the derived tree scope/controller plus both new classes, and16 actual compiled fact-policy cases passed. That is source evidence. Native guard linkage, an actual successful hive-producing feature, partial-failure restoration without drops/release, restart persistence, subsequent native UUID release/AI, visual ecology and resource costs remain pending. Do not plant until construction/function/art, fresh complete plots and current R5/cable/route protection are qualified. Do not suppress rare branches or retry toward a nest-free outcome.
