## Concrete successor

`prepare_source.derive(original_bytes)` hash-checks the unchanged active helper,
then creates a successor **outside** active sources. Parent replaces the existing
controller instance/registration, keeping its shared Interlock/Lease, commands,
bounded hashes, tickets, tick budget and cleanup. There is no second controller.
Compile that derived `ArtisticEngineeringSupport.java` together with
`NativeMillResumeAttachments.java` in a future bridge. Compile/linkage and actual
lever behavior remain unverified during the preview; do not deploy it as tested.

The successor accepts only `inspect` or `resume`; typed requests cannot cross
operations. It reconstructs all7,941 canonical targets from exact R3 base,
516-cell joined detail and94-cell depth sources. No placement, original BE stock,
filter initialization, kinetic attachment, rail propagation, link setter or
water-source phase can run. Existing connections are measured against the
original six actual curve UUIDs, endpoint offsets/directions, reciprocal links,
seven cells per span, native ownership and native collision-volume equality.
All3 original water sources and the actual existing flour filter must remain.

Resume requires a fresh stopped-save preimage over exactly those7,941 targets,
its completed native verification, then a separate fresh native inspection.
The controller also compares **every** current BlockState to that exact preimage
while verifying the source structure. Only independently bounded existing tube
fillers, water in the original wheelhouse AIR, and owned input flags can differ
from canonical authored source. Source/verification plans are NEVER placed.
The existing settlement verifier checks selected state properties and supplied
Items; it does not compare arbitrary BE NBT. This proposal therefore separately
reads actual native connections, cargo, filter, stations and all27 starter slots.
No source-only fixture is native acceptance.

## Actual item custody and normal input path

After stopped-drive/station/empty-cargo checks, each entrance is handled on the
server thread under the exclusive empty-world lease. The exact stock container
must still be the same native BE. It records CREATE_NEW durable intent, removes
one **real stocked** item, verifies its returned stack and every slot, records the
actual debit, then calls native `addTubeAttachment(WEST, attachment)` and verifies
readback. It never constructs a replacement inventory stack in-world, invokes
`Item.useOn` with a fake/null player, forges attachment NBT or refunds on failure.
The only stack copies are private expected-readback values.

The durable contract is independent of candidate/checkpoint so a rebind cannot
erase a prior debit/feed/assembly intent. A fully recorded first attachment can
be recognized when admitting the second; unresolved/foreign/mismatched intent
is refused. Real stock additions after a partial debit require explicit custody
reconciliation. Two clean committed attachments are followed by a normal WEST
lever neighbor notification. Only an OFF lever is normally turned ON. Native
LOCKED/POWERED must agree beforehand; no OFF/ON guessing and no direct entrance
flag setter. Readback reports actual lock/input memory, non-emitting WEST input,
side signal, lever state and output POWER=0. There is no invented paused field.

Only then does the preserved native RPM/stress wait permit the original real
16-wheat/one-ingot transfer and actual processing/routing/press checks. Separate
durable intents precede feed and assembly. A later partial failure is retained
and cannot rerun either callback; it needs a separately reviewed phase recovery.
Normal native stationary assembly/readback remains the original operation.
Passenger tube travel/train driving, restart persistence and function remain
future native gates even after a successful stationary resume.
