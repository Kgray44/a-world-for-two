# Exact Moonlight cached-provider proposal

This directory is isolated source. It is **not installed**, does not build or publish a pack, and does not establish SeedGen parity, accepted packets or generated LODs. The live candidate48 helper remains unchanged.

The actual48 client reached the existing resource attestation and refused `net.mehvahdjukaar.moonlight.api.resources.pack.CachePathPackResources`, pack `supplementaries:generated_pack`. This proposal recognizes only that exact observed provider and identity, with Moonlight1.21.1-3.7.2, its unchanged2,299,162-byte JAR SHA256 and three exact class resources. Other classes, subclasses, identities and cache implementations still refuse. It does not register every Moonlight provider, choose another storage strategy or silently treat a dynamic pack as empty.

The pinned cached wrapper is not a `PathPackResources` subclass. It owns its namespaces and original root bytes, and delegates data reads to either exact Minecraft `PathPackResources` or exact Moonlight `FastSearchPathPackResources`. The adapter reads that existing object graph and requires an initialized, ordinary available directory, matching wrapper/delegate roots and `SERVER_DATA` type. It never calls initialize, commit, clear, close or a resource-generation method.

The proposed integration independently walks and hashes the actual data files through the existing strict bounded path inventory. Every raw native namespace must be disclosed by the wrapper. It cross-checks original native resource listings and reads selected bytes through the original provider’s `getResource`; native root-resource bytes also remain original. Wrapper-declared empty namespaces are legal. A missing resource, stale/partial index, changed delegate, changed namespaces/root bytes, linked resource, invalid directory, changed artifact or uninitialized cache refuses. Unknown resources are never manufactured or normalized.

One initial draft assumption was disproved by the actual API fixture: the pinned FastSearch delegate reports an empty namespace set even with a populated index. The **wrapper** does not use that method for namespace authority; its `getNamespaces` returns its own manually populated set. The corrected adapter uses that original wrapper authority and still requires all independently discovered IDs to equal the original wrapper’s native list/get coverage. The failed drafts, compiled classes, exact source copies and diagnostics remain in private evidence. No real runtime/world action was involved, and no completeness requirement was dropped to accept an empty index.

The base owned attestation source is preserved as `LithostitchedSeedgenResources48-base.java.txt`, SHA `092b095e…`. `integration.diff` contains the exact additive provider branch. The original fingerprint format, codecs, registries, mod list, native loading phases, path grammar, selected-resource absence rules, pack order and effective override-stack hashing remain unchanged. The new cache view is rechecked after its inventory/read phase and again after the complete effective-stack capture. Absolute machine cache paths are not added to the fingerprint.

The offline Java21 fixture uses the actual unchanged provider classes and installed1.21.1/NeoForge dependency order. Its owned temporary object graph is wired to the two real native delegate alternatives without starting Moonlight’s loader-bound configuration/generation pipeline. It tests original metadata, complete directory/list/get coverage, root-level files, same-ID byte sensitivity, deterministic repeats, actual ordered `MultiPackResourceManager` stacks, cache/delegate mutations, stale indices, uninitialized caches, unknown subclasses/identities and changed JAR bytes. A supplemental genuinely initialized empty-cache case is kept separate from an uninitialized cache. Fixture object wiring is not evidence that the live loader’s module access or generation timing has passed.

The final fixture compiled and passed, including the initialized-empty-cache case. Its retained result has SHA256 `1bf3db1426cda0f7d80658a828bfe069f206541f06ba57aa89b7a65ce830869a`; the three source-boundary tests also passed. `source-freeze.json` binds the final sources and result. The earlier `integration-custody.json` is the preserved initial draft record; `final-integration-custody.json` binds the corrected adapter and final integration diff. Neither record establishes a native game lifecycle or current client/server parity.
