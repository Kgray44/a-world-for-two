# Guarded native chain construction proposal

This isolated source is **not integrated, compiled or run**. The current live
preview must continue undisturbed. Java compilation is deferred because the host
has less than1GiB available while KG's real client/server preview is running.
There is no executable request: the final3.5 hanging/frame source proof, native
geometry placement/verification and real stocked construction barrel are pending.

The source uses exact Reconnectible Chains2.4.4+1.21.1 and Ziplines1.5.3+1.21.1
public APIs. Original archives/source remain private. It creates the fifteen
ordinary north-faced knots on the proposed fourteen-span route, then attaches
only the consecutive native links with customSlack16. Geometry and source frames
belong to Grand's separate lane. No UUID is assigned/replayed and no entity NBT
is copied. Unregistered ordinary knot constructors generate their own UUIDs; a
forced durable file records all fifteen actual UUID intentions before the first
`ServerLevel.addFreshEntity`. Every add result and registered identity is checked.

The pinned normal player attachment flow consumes **one chain per directed link**,
with no separate knot cost. Native `attachChain` itself does not debit an
inventory. The new proposed town pavilion barrel at1221,65,−1273 must therefore
contain exactly14 ordinary chains in slot0 and nothing else before construction.
It is currently an unplaced empty source object, not a claimed actual inventory.
The controller journals each edge before removing one real item, durably records
the debit, then calls normal `attachChain(new ChainData(holder,CHAIN),null,true)`.
That null is the **previous-holder Entity**, not a player or an item-use callback.
Custom slack is set on the new link before the normal attachment. Native sounds,
packets, collisions and relative-position saving remain the mod's responsibility.

Any failure/cancel retains every actual partial entity, debit, drop and ledger.
There is no detach, discard, replacement, automatic refund or create replay.
Once a route ledger directory exists, create refuses. Uncertain partial custody
requires a separate diagnosis and reviewed recovery; this proposal supplies no
destructive cleanup command. Cleanup means only owned tickets/futures/lease.

## Admission and lifecycle

Proposed console-only commands are `awftchains create`, `inspect` and
`verify-restart`, each followed by a hash-named request bundle and exact SHA256.
`status` and `cancel` expose/stop the owned transaction. Integration must wire
`commands`, `tick`, `stopped` and `busy` into the existing shared maintenance
interlock. Instantiate lazily only when BOTH pinned common mods are loaded.
Do not expose a Chains type from an unconditional common static field, and do not
reference the client graph provider from this server helper.

The guards require an empty private25575 server, exact D:/world-tests home and
RosewaterArtistic world, owner receipt, seed, active/installed candidate pack,
actual bridge/native mod archives and loaded helper class hash. Paths are owned,
regular, bounded and nonredirected. The current stopped checkpoint is checked
again during work. Each full native geometry receipt must include a valid complete
marker, exact plan hash/count and zero failures/cleanup/futures/tickets. Create
requires fresh full proof; it also retains the real preplacement proof. Every
actual anchor and the new stock barrel must be covered by those full plans and
are rechecked against the live Level before mutation. Source frame/terrain proof
must use exactly the same fifteen nodes, slack16 and hanging offset3.5.

A current stopped-backup chain-knot census must scan all saved entity regions.
Create refuses any old knot within97m of any proposed anchor, so an unloaded old
relative link cannot silently adopt a new knot. Restart requires the same fifteen
saved UUIDs at their recorded blocks, with no nearby foreign saved knots. This
artifact is a real future scan prerequisite; no empty census is asserted now.
The live graph also refuses foreign resolved or unresolved incoming links.

Both actual config files and actual runtime fields are checked. Range96,
collisions enabled, hangOffset3.5, speed1, realisticPhysicsfalse and maxTurnAngle
0.707 are proposed reviewed values. Current43 still has range32/hang2.3 and is
refused; this controller never changes config files or runtime config fields.

The80m engine bound remains distinct from the≤48m conservative normal-reload
preference. Temporary maintenance loading proves structural persistence only;
it does not prove that a real rider normally tracks/ticks every longer span.
Before retaining an endpoint, the controller requires every column in its5×5
region neighborhood to be **already FULL**. It then uses at most16 explicit
endpoint tickets and create=false futures, with no new terrain-load authority.
If the preceding actual geometry verification has not left that finite footprint
ready, it refuses instead of generating terrain to make the test pass.

Passive `inspect` has no tickets or empty-server wake. Missing/unloaded endpoints
are UNKNOWN/failure, never presumed absent and recreated. `verify-restart`
requires a different actual JVM start time, the original durable completion and
real clean creation receipt. It retains only those already-FULL endpoint regions
for≤600 work ticks, allowing normal knot ticks to resolve the saved relative
holders. Only an unresolved link aimed at its exact recorded next block may wait;
foreign/missing identities, changed items, slack or decorations fail immediately.
The same fifteen UUIDs and fourteen resolved links must remain stable40 ticks.
All tickets/leases are removed afterward; no endpoint is kept loaded at idle.
Cleanup can retain its lease while an already-queued shared future completes and
reports that incomplete state honestly. It never cancels a shared future or
claims success before cleanup.

## Request protocol

`awft-native-chain-route:1` includes `allowed_operation`, exact candidate/bridge/
pack/checkpoint IDs and hashes, `native_class_sha256`, `bridge_jar_sha256`,
`zipline_jar_sha256`, and immutable `{path,bytes,sha256}` references to `route`,
the two canonical configs, `physical_frame_source` and `chain_census`. `geometry_sets` is a
bounded array of `{before,native_before,full,native_full}` references. Inspect
and restart additionally require the original actual `creation_receipt`.

The route is `awft-owned-native-chain-route:1`, route ID
`rosewater-cliff-town-v1`, exact world/seed/dimension and original geometry
checkpoint, fifteen `{block,face,anchor_state}` rows, fourteen `[i,i+1]` links,
slack16, hang_offset_required3.5, stock `[1221,65,-1273]`, stock_slot0, cost14 and
its actual verified stock block state. It explicitly says copied_entity_NBTfalse,
idle_forced_chunks0 and native_ride_acceptancefalse. On restart that immutable
original recipe stays unchanged; fresh full geometry evidence and the request
bind the current checkpoint. No old world-state preimage is replayed.

The proposed source-only frame envelope fields are `nodes`, `checkpoint_sha256`,
`slack`, `hang_offset`, `all_saved_AIR_clear`, `physical_frames_clear` and
`native_ride_acceptance:false`. These must be derived from the actual native-curve
and complete saved-frame sweep, not invented to satisfy this schema. Native
player/Level collision remains a separate gate even when source clearance passes.

The census format is `awft-stopped-chain-knot-census:1`, with current
`checkpoint_sha256`, exact `world_path`, `all_entity_regions_scanned:true` and
every saved chain knot as `{uuid,block:[x,y,z]}` in `knots`. It may only be
produced from the admitted actual stopped backup, including all entity-region
sources/provenance; a missing region or malformed entity is a refusal.

Compilation against the actual API, negative admission checks, native create,
cleanup, actual JVM restart, normal endpoint streaming in both directions,
survival boarding/handoffs/braking, two-player testing, performance and ornate
station photographs are all still pending. Source/API math is not a ride result.
