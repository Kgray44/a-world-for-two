The existing drink activity uses actual `farmersdelight:apple_cider` or
`farmersdelight:hot_cocoa`, chosen deterministically per resident. Both use
the installed native DRINK animation and32-tick duration; the actual registered
stack is checked before use. These are native mug item sprites with their
own third-person hand transforms, not a new3D tankard or decorative block cup.

LivingEntity performs the32 ticks and the item's native finish/effects/count/
container logic. The adapter never manually shrinks a drink, calls finish a
second time, invents an effect or replaces the Finish result. Any still-filled
native cup result is reused. A returned container stays held until the next
scheduled temporary-prop/activity transition under the existing managed-hand
policy. Temporary social props do not draw from player inventory/private stock,
drop accumulating containers, or create a separate inventory/economy system.
Farmer's Delight has player-specific consumption branches; a mob retaining its
native filled result is not represented as material consumption.

The added client-only PlayerModel TAIL mixin runs only for a tavern-skin NPC
actually using a native DRINK item. It follows native using hand, duration and
remaining ticks. Smooth arm/sleeve rotation leaves seated pivots/legs, root
position and instruments intact. The separate seat and sip passes commute:
one preserves arm rotations while the other preserves arm positions and legs.
No permanent drinking flag, fake player, new stock or ownership data is used.

The server observes native Finish events without modifying them. Status reports
real held item, using-item flag, remaining use ticks, use animation, starts,
native finishes and returned-result item. These observations do not establish
visible mouth placement or audio by themselves.
