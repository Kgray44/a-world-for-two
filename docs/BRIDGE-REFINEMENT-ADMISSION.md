## Why the old glue must be retired explicitly

Pinned Create 6.0.10 captures glue bounding boxes, discards their entities during
assembly, and creates new entities during disassembly. The old setup helper
looks for a deterministic UUID and does not remove older glue with another
UUID. Reusing setup alone would add the smaller glue while retaining the old
larger glue. Geometry matching is insufficient ownership evidence.

`tools.artistic_bridge_admission` reads authenticated immutable backups before
and after the earlier successful two-cycle test. It establishes the exact two
post-cycle UUIDs and complete typed NBT, then requires their unchanged presence
in the stopped candidate38 checkpoint and the new current checkpoint. No UUID,
raw NBT, seed or private save path is stored in this document. The reviewed
private origin document has SHA256
`dedfb17410b01b5996cdde1957e5f30a5f96f54a09f00cd28515da87bbf52453`.

## Small native integration

The original Java proposal is retained outside active sources at
`compat/bridge-refinement-admission/RefinementGlueAdmission.java`. Its exact source
copy is integrated under the bridge package in candidate39. Integration
copies that one class into the bridge package and wires its constructor,
`commands`, `tick` and `stop` through the existing lifecycle. Supply the current
candidate/version and the existing shared exclusive maintenance lease. Include
`busy()` in all competing maintenance admissions. This is one command owner,
not another listener or a replacement lease implementation. Acquire the lease
before assigning the operation's level so that shared admission does not reject
the operation itself.

The console-only command is `awftbridgeglue retire <bundle> <sha256>`; `status`
only reports and `cancel` retries retained cleanup. Before any removal it checks:

- Actual candidate, bridge class bytes, current checkpoint, origin and corrected
  physical-plan hashes; world identity and an immutable native preimage proof
  no older than five minutes.
- All 1,130 live preimage block states and absence of BEs at those targets.
- Both real bearings closed and disassembled; actual released controls, idle
  reversible 55-degree sequencers, initialized finite nonzero power and no
  overstress. Ready full chunks and actual entity simulation are required.
- Both exact saved UUIDs, exact class and boxes, no passengers, and complete
  current typed native `Entity.save` NBT. No field is filtered. An extra,
  unknown or changed glue fails admission. No moving/passenger contraption may
  occupy the reviewed bridge.

Both complete entities pass on the same server thread before either is
discarded. An immutable before journal must publish first. The two normal native
discards then execute without a yield, followed by exact after checks and a
terminal receipt. There is no automatic recreation or rollback if an unexpected
partial failure occurs. The actual partial state is retained for review.

Temporary tickets have exact retained handles and a bounded readiness timeout.
Failed removals retain the level, handles and exclusive lease, mark cleanup
required and block new admission. Explicit cancellation retries cleanup. No
idle/cleanup simulation wake or repeated journal loop runs. A terminal record
is usable only with its matching `.complete` hash, no error, zero remaining
tickets and cleanup false.
