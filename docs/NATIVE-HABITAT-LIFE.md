# Proposed native LIFE admission

This is an isolated implementation proposal. It is not registered in the active
bridge, installed in a game, or authority to seed the unfinished town.
Construction, functional commissioning, visual corrections and habitat review
must finish first. The frozen woodland proposal remains unchanged.

The owner's later direction supersedes its 116 manually modelled trees as the
default. The new expanded shore-to-cliff forest will primarily use qualified
native saplings/growth, with its own geographic and protection review. The
prepared 57-member, four-species set is an initial known-terrace population
proposal; it does not claim coverage of that entire expanded forest. Its
residents remain unspawned and must be rebound to the final actual habitats.

`tools.habitat_life` prepares new private artifacts under the owned staging
directory. It does not install dashboard requests, launch Java/Minecraft, spawn
anything or change a world. The initial policy admits only the pinned Naturalist
deer, birds, butterflies and fireflies whose actual classes/categories were
inspected. Two habitat groups form a batch, with at most 16 residents and 32
temporary chunks. Every member has a distinct actual footing and a complete
45-cell saved support/headroom preimage. A verification-only ordinary Settlement
Support plan addresses the combined habitat cells.

The producer scans **every saved entity region in the actual world**, including
dimensions and nested passengers. Reads are bounded to 64 regions/64 MiB total,
with one bounded decoded chunk at a time. It also checks saved-player filename
UUIDs without reading account inventories. Unrelated UUIDs and raw entity NBT
are not exported. A duplicate, malformed UUID, corrupt/incomplete input or
unbounded census refuses preparation. Retained original recipes preserve the
population identity when preparing later inspections against a new checkpoint.

## Native transaction

The proposed `NativeHabitatLifeSupport` accepts console-only `awftlife inspect`
or `awftlife seed` requests on the **empty, owned private port 25575**. A command
cannot upgrade an inspect request into seed authority. Admission binds the exact
request, candidate, bridge, helper and policy class bytes, platform, installed
pack, current verified checkpoint, seed/world path, immutable recipe and complete
UUID census. The Naturalist JAR is hashed incrementally with file identity,
size/time stability checks. The existing shared `ArtisticEngineeringSupport`
Interlock/Lease provides exclusive ownership. No additional global force/wake or
`resetEmptyTime` is used. Temporary native ticket handles and shared futures are
retained until real cleanup succeeds; failed removals require an explicit cancel
retry. A pending cleanup prevents new work.

All members are validated before spawning begins. The actual registered type,
native class/category, block preimage, support, fluids, entity collision,
obstruction and ordinary spawn rules must agree. New mobs come from the native
factory, use `MobSpawnType.STRUCTURE`, ordinary NeoForge spawn checks and
`EventHooks.finalizeMobSpawn`, then normal `addFreshEntity`. The real spawn-cancel
flag is checked through its exact patched native API. No copied NBT, fake player,
NoAI switch, forced owner/tame state, health/age/variant invention or arbitrary
commands are accepted. The native initializer selects ordinary variant data.

Before adding a resident, an immutable per-UUID intent is created and flushed
under the **actual world's data directory**. An admitted marker follows actual
native readback. A crash can leave an intent without a loaded entity; this is
uncertainty, never permission to replace it. A fresh census can locate an
existing owned resident, but its actual type, class, tags, dimension and roaming
habitat must match the retained ledger. Existing gameplay ownership is observed
and preserved. Loaded UUIDs in other dimensions or duplicate saved UUIDs refuse
admission. No rollback removes real residents.

An inspect operation creates only unadded native preview objects; it does not
finalize/add mobs or write a population ledger. Journals distinguish native
identity/AI-flag checks from later behavior, visual and performance evidence.
Ordinary AI progress must be observed with a real player later. A successful
transaction still needs zero remaining temporary tickets, shared futures and
lease ownership. Actual terminal receipts remain immutable with completion hashes.

## Parent integration and remaining gates

1. Review and copy the two proposal Java files into the bridge source tree for
   the next parent-owned candidate. Their present location is deliberately
   outside the normal build's `src` discovery.
2. Instantiate the helper with the exact candidate/bridge and `this::acquire`.
   Register its commands, tick it in the same server thread as NativeImportJoins,
   and call `stopped()` during teardown. Include `life.busy()` in all shared
   admission checks, including pending cleanup. Do not create another listener
   or independent ownership mechanism.
3. Recompile in an owned bounded directory and bind both actual class hashes.
   Prepare **inspect** artifacts against the new stopped checkpoint. Parent may
   explicitly install only the selected request into its hash-named dashboard
   input directory; referenced recipes/census remain private immutable artifacts.
4. Complete the exact new plaza/fountain AIR, basin/plumbing and sightline mask.
   The seed producer rejects forest/plaza conflicts rather than trimming them.
   Trees/understory use ordinary native settlement placement and strict current
   verification; leaf-distance/survival expectations need their separate native
   derivation. No resident command substitutes for planting verification.
5. After construction/function/art are complete, parent supplies a current
   reviewed LIFE approval listing `approved_recipe_sha256s`, and the fresh
   completed native habitat verification. The request carries the exact verified
   habitat plan, whose full states must cover every member's 45-cell witness;
   an unrelated successful building verification cannot authorize LIFE.
   Only then prepare seed requests.
6. Exercise native inspect, spawn cancellation, positive idempotence, interrupted
   ledger refusal, actual owner preservation, cleanup and restart in the private
   world. Then observe real AI, coexistence, habitats and CPU/RAM/MSPT/chunks.

The same admission pattern can later serve cats, dogs, villagers, peaceful
magical residents, insects and aquatics, after each exact native class and its
habitat/behavior requirements are reviewed. Water depth/shore-exit conditions and
villager beds/jobs are not inferred from category names. These species are not
silently enabled by the initial four-species allow-list.
