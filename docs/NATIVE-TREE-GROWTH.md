# Native woodland growth proposal

This isolated proposal grows actual registered saplings through the pinned native `BonemealableBlock` APIs. It creates no hand-stamped default tree and no fake player, and claims no consumed bonemeal inventory. The earlier manual-tree study is historical; it is not the forest implementation.

The initial selection is birch plus Regions Unexplored magnolia, white/pink magnolia, maple, silver birch, pine, larch and golden larch. Every selected runtime block must actually be a supported `SaplingBlock`. The `describe` operation records its real `TreeGrower`, primary, secondary, flower and mega feature keys, and the registry-aware configured-feature codec data. Those actual descriptors, including rare variants, must be reviewed before deriving a species envelope. A small-looking default tree is not evidence that its larger variant fits.

The pinned Regions Unexplored artifact is 0.6.3, 6,641,783 bytes, SHA-256 `e7f2edd7bab869c2e566b1b251ea54c6b95834205276bf3a302859d72d9d0c9b`. The helper hashes its actual loaded file and binds the current candidate, bridge classes, pack, owned private world and verified stopped checkpoint. Native admissions additionally require an immediate private stage under `D:/A World for Two/staging/world-tests` and its exact `world/RosewaterArtistic` save, on port 25575 with no players. Upstream feature implementations are not copied into this repository. The author's [Regions Unexplored source](https://github.com/Apollounknowndev/RegionsUnexplored) and the pinned artifact inform the review; the runtime codec is the authority for the selected configuration.

## One finite plot

`tools.native_tree_growth` prepares a new private folder only. `describe` emits an inspection request and reads no terrain. `review` emits a concrete saved before-plan, protection and tree-plan hash **without an executable request**. After construction, functional work and visual corrections are complete, `grow` additionally requires a review bound to that exact tree-plan and checkpoint. Parent integration and explicit installation remain necessary; preparation does not install or execute anything.

Each plot has a qualified whole-feature write envelope and a fully known read/physics perimeter: eight blocks horizontally, two below and four above. Every saved voxel must come from authenticated FULL chunks. Missing or non-FULL data is unknown, including the perimeter; neither an Atlas tile nor a sampled dry center permits planting. Existing natural trunks/canopy, wet channel cells, block entities and high obstructions reject the plot. All authored targets, including AIR routes, furniture, plumbing, latest plaza/view reservations and contour-walk clearances, retain their complete five-block horizontal skirt. The entire growth envelope must avoid that protection, not merely its root.

The final forest must use the expanded, actual connected south bank and the missing cliff-foot survey. The historical small terrace and 57 example residents do not establish whole-shore coverage. The final R5 plaza reservation must replace the earlier mask before any growth admission.

## Real-level guard and failure behavior

The isolated dedicated-server mixin intercepts native `Level` block, fluid and block-entity reads and block writes only while a synchronous leased growth call is armed. Its inactive path checks one volatile flag before consulting `ThreadLocal`; it performs no client rendering work. Before planting, a real read/write sentinel must prove both hooks are installed. A missing hook refuses the operation before sapling placement. This is a real-level guard, not a virtual world or a replacement renderer.

Reads outside the complete known field and writes outside the owned envelope are refused. Existing solid objects, fluids, trees and native block entities are preserved. Actual entities inside the growth box and a one-block margin refuse planting; no residents, passengers or objects are moved to make room. A latched violation cannot be hidden by a feature swallowing an exception. Only air, explicitly allowed soft vegetation and native dirt below the root are editable. Twelve native success trials are the absolute limit. A stage-one feature failure ends the attempt; it is not repeatedly forced until a preferred variant appears. The scope is never left armed between ticks and no uncommitted sapling is left to grow later outside the transaction.

A successful call archives the literal before and native after fields, actual native block-entity data and feature descriptors. It must observe a real trunk/canopy and no untracked changes. That proves native generation only; tree silhouette, cohesion and ecological placement still need actual native views.

A failed call latches possible residual state before attempting failure evidence. A failed snapshot or block-entity capture cannot skip restoration. The helper restores only the exact cells touched by that scoped attempt through normal native setters; the complete field and preexisting block entities must then match. Unavailable failed-state evidence is explicitly marked unavailable. Restoration never replays inventories or entity ownership. Any unproved restoration or scope closure produces a private quarantine receipt and blocks further tree attempts until an exact reviewed recovery; an in-memory latch also remains if the quarantine file cannot be written. It does not silently accept a partial tree. Temporary tickets and shared futures remain owned until real cleanup succeeds, with a console cancel retry for cleanup. No permanent chunk force or global idle wake is introduced.

## Parent integration and pending native gates

Copy the three reviewed Java proposal classes into the bridge's existing source layout and merge `NativeTreeGrowthGuardMixin` into its existing **server** mixin list. Wire one `NativeTreeGrowthSupport(candidate, bridge, sharedInterlock)` instance into the existing command, server tick, stop and maintenance-busy lifecycle, using the same interlock as native engineering/import work. Do not register a second listener or independent lease manager. The producer binds actual compiled class hashes and emits the exact private request references; installation copies only those reviewed inputs to the expected dashboard location.

Before a native run, perform a fresh bounded ReserveGuard check for both drives and budget the known chunks, save changes and up to two 16 MiB outcome archives. The monitoring rule cannot constrain other applications or existing writers.

Pinned API compilation, focused producer fixtures and the compiled recovery-orchestration probe are source-level evidence. The probe injects snapshot/BE-capture and restoration failures without constructing a Minecraft level. Actual Mixin transformation, runtime descriptor inspection, guarded sapling growth, deliberate escaped-envelope failure/restoration, ticket cleanup, save/restart persistence and shader views remain native validation gates. Features using asynchronous or direct-chunk writes are unsupported until their actual pinned implementation is reviewed; no success is inferred from compilation. Wildlife uses the separate frozen habitat proposal and follows final construction and habitat admission.
